前言

考過CCNA，但發現網路還有一些奇怪設定在此留下紀錄

  1. DHCP 避讓 Static ARP (靜態 ARP) 、DHCP 位址保留 (DHCP Reservation) 很多廠商（特別是中低階設備）是把 DHCP Server 模組與 ARP Table 模組分開寫的 交換器端：手動設定固定 IP（例如 192.168.1.2），遮罩 255.255.255.0，閘道指向路由器 192.168.1.1。 路由器端 (TP-Link)：進入 DHCP 設定，將發放範圍（Pool）修改為 .100 到 .254。 結果：.2 到 .99 變成「手動保留區」，DHCP 永遠不會去動這區，自然不會有衝突。

  4. hostname 建議用名字不要用fqdn，雖然不影響dns解析，但影響的是區域網路 (mDNS / NetBIOS)，單純名字解析就變成vivi.local可以找,但設定vivi.com 無法vivi.com.local找到

Proxmox IPAM分配192.168.10.0/24 網段,路由器是用192.168.8.0/24網段 ASUS 網路 / 主機 IP10.0.0.0告訴路由器：這是你要找的 PVE SDN 目的網段（後面的 .0 代表整個網段）。若你的 SDN 是 10.1.1.x，這裡就填 10.1.1.0。 網路遮罩 255.255.255.0通常 SDN 的子網路遮罩預設是 /24，對應成 IP 格式就是 255.255.255.0。 閘道器 192.168.8.100關鍵！ 請填入你的 PVE 主機在實體家裡的 IP。這代表當有封包要去 10.x 時，ASUS 路由器會把封包丟給這台 PVE 主機，由它帶路送進 SDN。順序 (Metric)1 或 10路由的優先權，通常填寫 1 或 10 即可（數字越小優先度越高）。 介面 「LAN」 但是裡面10通不了外面8

上游 DNS（Upper DNS） dnsmasq server=/lab/192.168.10.53 DNS 條件轉發（Conditional Forwarding） DNS 字尾（DNS Suffix）讓你的電腦知道 internal 是一個正統的內網域名，你必須透過剛才那台華碩路由器，把這個後綴強行塞給電腦的系統核心

mDNS跟自架DNS是可以共存，mDNS 負責發現DNS 負責管理，2013年RFC 6762 正式將 .local 劃歸為 Multicast DNS (mDNS) ,所以看到local第一反應是發送廣播封包而不是問dns
