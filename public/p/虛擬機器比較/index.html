虛擬機器比較

Aug 04, 2026
2 minute read

Oracle VirtualBox

網路模式 VM 上網 VM ↔ VM 主機 ↔ VM 區網設備連入 VM 適合用途
NAT ✅ ❌ 預設不行 主機連 VM 需轉發 ❌ 需 Port Forwarding 單台 VM 單純上網
NAT Network ✅ ✅ 主機連 VM 需轉發 ❌ 需 Port Forwarding 多台 VM 組成可上網的實驗網路
Bridged Adapter 橋接 ✅ ✅ ✅ ✅ 讓 VM 成為實體區網中的一台電腦
Host-only Adapter ❌ ✅ ✅ ❌ 主機與 VM 的封閉實驗網路
Internal Network ❌ ✅ ❌ ❌ 完全隔離的 VM 內部網路
Not Attached ❌ ❌ ❌ ❌ 模擬網路線被拔掉
Generic Driver 視設定 視設定 視設定 視設定 UDP Tunnel、VDE 等特殊用途
Cloud Network 視雲端設定 視設定 視設定 視設定 將本機 VM 接到 Oracle Cloud
  • 只想讓一台 VM 上網：選 NAT
  • 多台 VM 要互通又要上網：選 NAT Network
  • VM 要直接出現在家裡的 192.168.8.0/24：選 Bridged Adapter
  • 只有主機和 VM 需要互通：選 Host-only Adapter
  • 建立完全封閉的多台 VM 實驗室：選 Internal Network
  • 做完整路由器／防火牆 Lab：使用 NAT + Internal Network 雙網卡

特色功能

  • VM 畫面與聲音直接錄製
  • VRDP：不用依賴 Guest 的 RDP
  • UDP Tunnel:跨兩台主機建立虛擬網路
  • VISO：不用真正建立 ISO
  • 快速Clone
  • 純軟體模擬KVM

Hyper-V

功能 Hyper-V 的特點 相較 VirtualBox／一般 KVM
Type-1 Hypervisor 啟用後 Hyper-V 直接控制硬體，原本的 Windows 變成 Root Partition VirtualBox 是 Hosted 架構；KVM則同樣接近 Type-1
Dynamic Memory VM 執行中依需求自動增加或回收記憶體 VirtualBox 沒有同等完整機制；KVM ballooning 能做到但策略較分散
Production Checkpoint 透過 VSS／檔案系統凍結建立應用程式一致快照 比一般「直接保存記憶體狀態」更適合正式伺服器
Hyper-V Replica 不需要共享儲存，直接將 VM 非同步複寫到另一台主機 VirtualBox 幾乎沒有；Proxmox 可用 replication，但通常依賴 ZFS/叢集
Windows Failover Cluster VM 故障後可在其他節點自動啟動 企業版核心優勢，VirtualBox 不具備
Shared-nothing Live Migration 不使用共用 SAN，也能在線遷移 VM KVM 也能做到，VirtualBox Teleporting 沒這麼完整
Storage Live Migration VM 執行中移動 VHDX 到其他儲存位置 比 VirtualBox 的儲存遷移成熟
Shielded VM vTPM、磁碟加密、Host Guardian，連主機管理者也不一定能讀 VM Hyper-V 很有代表性的企業安全功能
Enhanced Session Mode VMConnect 可轉送剪貼簿、磁碟、USB、印表機、音訊及解析度 類似 VirtualBox Guest Additions，但對 Windows Guest 整合特別好
PowerShell 完整管理 幾乎所有 VM、網路、儲存與叢集功能都能腳本化 很適合大量建立 Windows Lab
Windows 平台共用 WSL2、Windows Sandbox、VBS、Credential Guard、Hyper-V Containers 共用 Hyper-V 架構 是其他桌面 Hypervisor 沒有的生態整合
Hyper-V Virtual Switch

Windows Server 才是完整企業版：

  • Hyper-V Replica
  • Failover Clustering
  • Live Migration
  • Storage Migration
  • Shielded VM／Guarded Fabric
  • 大型 NUMA 與硬體擴充
  • SR-IOV、RDMA、DDA 等伺服器功能
